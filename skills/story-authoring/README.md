# story-authoring

## Goal

Turn product work into accurate, executable stories by verifying the current state, selecting the
type from the actual outcome, splitting mixed work, writing testable acceptance criteria, and
keeping missing product decisions explicit.

## When to use

1. An idea or request needs to become a Feature, Design, Bug, Chore, or Release story.
2. An existing story is vague, stale, oversized, or mixes unrelated outcomes.
3. Acceptance criteria sound plausible but are not independently testable.
4. An agent is about to create or update an issue in a tracker.
